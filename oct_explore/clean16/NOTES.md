## Methods, code and deviations

Code: `oct_explore/clean16/` (`common.py`, `qaoa.py`, `gcost.py`, `native.py` + `native_prog.py`, `wsat.py`, `verify_k.py`, `report.py`); raw per-formula p in `oct_explore/results/clean16/*.json`, logs in `oct_explore/logs/clean16/`.

- **K-cavity generalisation.** The frozen compiler maps n=20 to the 32-level layout [5,5,5,5]. For this study `common.py` overrides `compiler.LAYOUTS[20] = [4,4,4,4,4]` **in memory only** (no frozen file edited; hash check still passes). Everything else (nsim, frozen_circuit.circuit_p, chain projection mask) was already generic in K. Checks (`verify_k.py`, `logs/clean16/verify_k.log`): (a) K=4, old F16_qaoa angles on old TEB n=16 formula #0 reproduce the stored p exactly (0.0304884); (b) K=5 n=20 cavity-chain simulator vs an independent numpy qubit-QAOA statevector: 0.0123747 vs 0.0123746; (c) frozen `circuit_p` (global cost, w=0) at K=5: 0.0123747. Chain Walsh-support mask counts 256/496/736/976 = 1+15K+225(K−1) for K=2..5, as expected.
- **QAOA L4** = `v3/native/fixed.py --proj full --mixer gray` (the old 34.82 baseline code; ideal one-bit-flip mixer on 4-bit cavities = product of qubit RX), copied to `qaoa.py`. 1000 train formulas per n, L-BFGS from 12 starts, best train loss kept. Seed changes only the 8 random starts (the 4 deterministic linspace starts are shared), so seeds can converge to the same angles. The old `QAOA_n6_L4.json` warm start was disabled (nothing reused).
- **Global cost L4** = `v3/native/gnnw.py` G16_full_w recipe (`--proj full`, block assignment, GNN clause weights + per-formula g/b deltas, 3000 Adam steps, 5000-formula pools per n, early stop on val n=12) copied to `gcost.py`. **Deviation:** the old run warm-started the backbone from `results/v3/S_g4_snapF_s1.json` (trained on old data); here it is trained **from scratch** (`--warm ""`), with base angles `--x0` = the fresh QAOA winner (same role as F16_qaoa.json in the old recipe). gnnw's own early stopping uses the same val n=12 set (validation only).
- **Native best** = net16r ckpt_110 `best_program.py`, copied to `native_prog.py`; the only edit is exposing the training-RNG seed (`default_rng(0)` → `default_rng(SEED)`, seed 0 = original). The program needed no change to run on 2–5 cavities. Trained with its own `train(api, 180 s)` exactly like the net16r evaluator (OE_TRAIN_N=8,12, 600 formulas per n, R=4 placements: min-cut + 3 seeded random). Scored round-robin 1/mean_r p_r with the unchanged frozen `circuit_p`; at n=20 entries are simulated one at a time to bound memory (same math).
- **WalkSATlm** = `qaoa_ksat/walksatlm_c/wslm.c`, p=0.30, w1=6, w2=5, n-flip tries with restarts, 500 runs per formula averaged; lookups = tries + flips.
- **Train-set sizes** follow each method's recipe (QAOA 1000, global cost 5000, native 600 per n), all drawn from the same fresh base 51e9 (nested prefixes of one stream).
- **Mixer (all quantum methods): the IDEAL one-bit-flip mixer** M(β) = ∏_j exp(−iβX_j/2) on each cavity's 4 Gray digits (`nsim.Mixer(4, "gray")`), i.e. the target unitary the calibrated SNAP-D-SNAP sequence is fitted to. No calibrated/native SNAP-D-SNAP mixer matrices are used anywhere in this table (QAOA, global cost and native alike), so mixer calibration error is not included.
- Bug caught during the run: the first QAOA launch omitted `--proj full` (fixed.py default is `chain`), giving the chain-projected baseline (n=16 450/7796); it was discarded (`results/clean16/discard/`) and QAOA was rerun with `--proj full` (now the default in `qaoa.py`).
- QAOA seeds 0 and 1 converged to identical angles (same best start); seed 2 found a different optimum.
